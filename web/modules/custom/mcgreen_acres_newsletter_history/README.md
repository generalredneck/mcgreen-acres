# McGreen Acres Newsletter History

Surfaces the Simplenews **subscriber history** log in the admin UI.

Simplenews (since the 3035367 work) records every confirmed subscribe /
unsubscribe as a `simplenews_subscriber_history` entity, capturing the acting
user and the route the request hit — but it never shows this anywhere. The only
way to read it was a raw DB query. This module adds a **History** tab to each
subscriber:

`/admin/people/simplenews/edit/{id}/history`

and a **History** operation link on the subscriber list at
`/admin/people/simplenews`.

## What the table shows

| Column | Meaning |
| --- | --- |
| When | Timestamp of the change |
| Change | Subscribed / unsubscribed / changed, derived by diffing each record's newsletter set against the previous one |
| Subscribed after change | Newsletters the subscriber held immediately after this event |
| Source | Human label for the recorded route, e.g. *Signed up from a page or article (`entity.node.canonical`)*. An empty route (Drush, cron, import, migration) shows as *Programmatic*. The raw route name is always shown in parentheses so it stays greppable. |
| By | The acting user — *Anonymous / self-service* for `uid 0`, otherwise a link to the user |

## Known limitations (candidates for upstream — see drupal.org #3384939)

- History rows are matched on the subscriber's **current** email. If an address
  was changed, events recorded under the old address are not shown.
- `simplenews_subscriber_history` has **no access control handler** upstream;
  the tab is gated by the route permission
  (`administer simplenews subscriptions` or `view simplenews subscriptions`).
- The `mail` column on `simplenews_subscriber_history` is **unindexed** upstream.
  Fine at current volume; revisit if the table grows large.
- Simplenews only records history while a subscriber is *confirmed*, and only
  since the release that added tracking. Older activity will not appear.

## Tests

`tests/src/Kernel/SubscriberHistoryBuilderTest.php` exercises the builder against
real history rows generated by subscriber saves (subscribe, add newsletter,
unsubscribe, unsubscribe-last, email scoping, programmatic source label).
